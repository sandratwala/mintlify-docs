---
title: "Glossary"
---


This glossary defines the technical terms, system components, technologies, and domain-specific terminology used throughout the Probe technical documentation.

| **Term**                  | **Definition**                                                                                                                                                                                               |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **API**                   | Application Programming Interface — a set of HTTP endpoints exposed by the backend that allows the frontend and other clients to communicate with the system.                                                |
| **JWT**                   | JSON Web Token — a signed authentication token issued after login and used to authorize requests to protected API endpoints.                                                                                 |
| **CORS**                  | Cross-Origin Resource Sharing — a browser security mechanism that controls which frontend origins are allowed to communicate with the backend API.                                                           |
| **bcrypt**                | A password-hashing algorithm used to securely store user passwords as hashes rather than plain text.                                                                                                         |
| **Passlib**               | A Python library used by the backend to manage password hashing and verification using bcrypt.                                                                                                               |
| **ORM**                   | Object-Relational Mapper — a technique used by SQLAlchemy to represent database tables as Python classes and interact with the database using application-level objects.                                     |
| **SQLAlchemy**            | The Python ORM used by Probe to define database models and interact with the PostgreSQL database.                                                                                                            |
| **Alembic**               | A database migration tool used to version, manage, and apply changes to the PostgreSQL database schema.                                                                                                      |
| **PostgreSQL**            | The relational database management system used by Probe to store users, devices, batteries, sensor readings, bookings, and related data.                                                                     |
| **MQTT**                  | Message Queuing Telemetry Transport — a lightweight publish/subscribe messaging protocol used for communication between the hardware devices and the Probe data pipeline.                                    |
| **HiveMQ**                | The MQTT broker used by Probe to receive raw sensor readings from the ESP32 and distribute processed battery data to connected system components.                                                            |
| **ESP32**                 | A microcontroller used in the Probe hardware to collect sensor measurements and transmit temperature, voltage, and current data through MQTT.                                                                |
| **Sensor Reading**        | A set of measurements collected from the battery testing hardware, including temperature, voltage, current, State of Health, category, and status.                                                           |
| **SOH (State of Health)** | A calculated indicator representing the tested condition of a battery. In Probe, SOH is determined using a hardcoded calculation based on battery measurements rather than a trained machine-learning model. |
| **Battery**               | A battery asset registered in Probe and associated with a recycler, testing device, sensor readings, and potentially one or more bookings.                                                                   |
| **Device**                | A Probe hardware testing unit identified by a unique serial number and associated with a recycler and battery-testing channels.                                                                              |
| **Recycler**              | A Probe user with `user_type = RECYCLER` who manages battery inventory and operates the battery-testing hardware.                                                                                            |
| **UPS Company**           | A Probe user with `user_type = UPS_COMPANY` who can view available battery inventory and request batteries through the booking workflow.                                                                     |
| **Admin**                 | A privileged Probe user with `user_type = ADMIN` who has access to administrative functionality and restricted API operations.                                                                               |
| **Booking**               | A request made by a user to reserve available battery stock from a recycler. A booking moves through defined statuses such as `PENDING`, `CONFIRMED`, `CANCELED`, and `COMPLETED`.                           |
| **RBAC**                  | Role-Based Access Control — a security mechanism that restricts system functionality according to a user's assigned role.                                                                                    |
| **Bearer Token**          | An authentication credential included in the HTTP `Authorization` header to allow access to protected API endpoints.                                                                                         |
| **Preflight Request**     | An HTTP `OPTIONS` request automatically sent by a browser before certain cross-origin requests to determine whether the actual request is permitted by the server's CORS policy.                             |
| **Environment Variable**  | A configuration value stored outside the source code and used to provide environment-specific settings such as API URLs, database credentials, and authentication secrets.                                   |
| **Config Var**            | Heroku's term for environment variables configured through the application's dashboard.                                                                                                                      |
| **Dyno**                  | Heroku's term for the isolated container/process used to run an application.                                                                                                                                 |
| **FastAPI**               | The Python web framework used to build Probe's backend REST API.                                                                                                                                             |
| **Next.js**               | The React-based framework used to build the Probe web dashboard.                                                                                                                                             |
| **Flutter**               | The cross-platform UI framework used to build the Probe mobile application.                                                                                                                                  |
| **Dart**                  | The programming language used to develop the Probe Flutter mobile application.                                                                                                                               |
| **REST**                  | Representational State Transfer — an architectural style used by Probe's API to expose resources through HTTP methods such as `GET`, `POST`, `PATCH`, and `DELETE`.                                          |
| **Swagger UI**            | An interactive web interface automatically provided by FastAPI that allows developers to explore and test API endpoints.                                                                                     |
| **Postman**               | An API development and testing tool used in Probe to send requests, verify responses, test authentication, and perform regression checks.                                                                    |
| **Vercel**                | The hosting and deployment platform used for the Probe Next.js web dashboard.                                                                                                                                |
| **Heroku**                | The cloud platform used to host the Probe FastAPI backend and provision the PostgreSQL database.                                                                                                             |
| **Repository**            | A software component responsible for direct interaction with a specific database resource, following Probe's layered backend architecture.                                                                   |
| **Service**               | A backend layer responsible for implementing business logic and coordinating operations between routers and repositories.                                                                                    |
| **Schema**                | A Pydantic model used by the FastAPI backend to validate incoming request data and structure outgoing API responses.                                                                                         |
| **Router**                | A FastAPI module containing the HTTP route definitions for a particular resource, such as users, batteries, devices, or bookings.                                                                            |
| **Telemetry**             | Measurement data continuously or periodically collected from hardware devices, such as battery temperature, voltage, and current.                                                                            |
| **API Endpoint**          | A specific URL and HTTP method through which a client can interact with a backend resource or operation.                                                                                                     |
| **Environment**           | A specific runtime configuration of the application, such as local development, staging, or production.                                                                                                      |
